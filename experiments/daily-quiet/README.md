# Daily quiet context — portable presentation experiment

This opt-in Claude Code mod removes a selected engine progress nudge, omits the initial email context block, and rewrites reviewed prose fragments in engine/core tool descriptions. It preserves tool execution, parameter schemas, deferred placement, instruction-file metadata, task results, hook/plugin context and unknown text. Runtime owners retain their own authorization, recovery, identity and delivery paths.

它让日常 context 的展示规则可独立检查与迁移。规则不检查 CC version：已审片段用 SHA-256 精确识别，新参数与未知段落保留，已改写的原厂片段会退回原文，等待重新审阅。不要把“没有命中”当成整个版本不能使用，也不能承诺未来所有 CC 都已兼容。原厂提示全文、真实身份与聊天均未收录。

## Try the synthetic comparison

From the repository root, with Python 3.10+ and Node.js:

```sh
node --test experiments/daily-quiet/tests/rules.test.mjs
mkdir -p .cache/daily-quiet
node experiments/daily-quiet/demo.mjs > .cache/daily-quiet/input.json
python3 scripts/run_context_case.py .cache/daily-quiet/input.json --out .cache/daily-quiet/result
python3 scripts/build_context_atlas.py --case .cache/daily-quiet/result/case.json
```

The demo uses invented bodies and an explicitly synthetic description rule. It executes the real pure rule functions and existing case checker, compares baseline/candidate/native-text-update, and leaves real resume, model behavior and external delivery unassessed. It is not a recording of a lifecycle or a prediction of conversation quality. `case.json` and reports retain the declared inputs; no default example contains private data.

## Use the mod in an explicitly selected session

Review `hooks/quiet-rules.mjs` and the supported API for your trusted binary first. Validate and test without calling a model:

```sh
claude plugin validate ./experiments/daily-quiet
claude plugin test ./experiments/daily-quiet
```

An isolated config is recommended for these checks. The native test kit uses synthetic events; it neither loads your normal runtime hooks nor calls a provider. A normal validation exit of zero is not plugin-directory acceptance: catalog licensing, README and other directory requirements are separate.

To load the reviewed mod for one session, use the native `--plugin-dir ./experiments/daily-quiet` option. This does not replace your core, change permissions, disable tools, install a global plugin, stop compaction or alter transcripts. Choose configuration such as Git guidance and bundled-skill visibility in your runtime owner; attribution is a separate author choice.

已有 middleware 若不调用 `next`，会截住下游 handler。受管 runtime 应把纯规则接到它已有的 canonical entry，不应叠第二份入口猜顺序。本目录的 `register.mjs` 是独立会话的薄接线，`quiet-rules.mjs` 是唯一纯规则 source；受管消费者可以保留带 revision/provenance 的 frozen copy，并在升级时核对字节一致。

## Upgrade and evidence contract

- Only `origin.kind=engine` plus the selected attachment type is omitted. No global tag or keyword stripping.
- Tool rewrites require `provider.plugin=engine`, `provider.tier=core`, the selected tool and an exact reviewed fragment. Parameter schema and unknown facts are not rewritten. GitHub notification facts remain when their surrounding style guidance is shortened.
- `claudeMd` is kept as supplied. Native context tracking is tied to agreement between rendered text and `instructionFiles`; synthetic native tests supply a coherent initial file record and verify its survival.
- Quiet presentation does not grant exact recovery. A consumer whose history mutation depends on a verified build must keep that independent gate; ordinary CC updates can continue with quiet filtering and unsupported recovery disabled.
- A partial `api-request-shape` containing only system/tools cannot prove messages, server-side instructions or provider receipt. Use explicit scope rather than inventing an empty history.

2026-11-01 evidence: Node pure rules and middleware checks passed; isolated Linux CC 2.1.314 and 2.1.316 native test kits passed three synthetic tests each. Native validation passed with catalog warnings, before a public license decision. These are loader/event-contract results, not full request, lifecycle, model-quality or delivery acceptance. See [portable evidence](../../references/daily-quiet.json).

## Provenance and limits

The rules and synthetic fixtures are project-authored. Digests identify specific reviewed native prose fragments; they do not contain the original prompt text or impose a binary version pin. The public API is described by the [official Mods reference](https://code.claude.com/docs/en/plugins/mods/reference); use the declarations generated by your exact trusted build when they differ from public docs.

This experiment forms one bounded comparison within the broader [context programme](../../docs/development-programme.md). It does not replace the general observer, context case, Memory/state owners, Forge research or runtime deployment procedure. Public visibility and reuse terms remain separate release decisions.
