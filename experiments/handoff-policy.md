# Handoff 与 curation 的候选写作合同

日期：2026-10-05。状态：**原创研究草案，未做模型实验、未安装、未接入 runtime**。这不是可执行 Skill，也不规定新的 Memory schema。接口选择见 [Compact control](../docs/compact-control.md)，来源、状态与验收原则见 [Continuity and Memory](../docs/continuity-and-memory.md)。

这份草案把内容判断做成可单独比较的输入。现有 runtime 的六字段 handoff、大小限制和 writer authority 继续由原 source 拥有；采用草案时需要明确映射，不能把下列 Markdown 直接冒充该协议的有效输出。

## 给 handoff writer 的候选正文

```text
为下一次续接写一份 handoff。使用当前会话已有的自然语气；能区分说话者时可以用第一人称，但保留谁说了什么、发生在何时、哪些来自旧摘要。只依据给定材料，不补写未交付的原文、工具结果、感受或感官细节。

输入可能包含上一次 handoff、本次新增事件、近期完整原话，以及覆盖范围与可用预算。先吸收更新，再写当前状态；不要逐段照抄旧摘要。若来源缺失或预算不足，写明缺口，不声称完整。

按下面的阅读顺序组织；没有内容的部分可以省略：
1. 此刻：双方近况、最后在做什么、对话氛围与注意停点；临时状态标明时间。
2. 重要经历：发生了什么、为什么有意义。关键原话仅在原文可见时引用，其他内容标为转述或继承。
3. 正在做的事：进展、结果、当前采用的决定及理由；保留提议、决定、被否决方案之间的区别。
4. 仍然活着的愿望、偏好与约定：归属、条件、来源及较新修订。一次意向不升级为稳定偏好；重复继承不算独立确认。
5. 错误与纠正：记录具体事件、结果和已经接受的纠正，不从单次事件编造长期规律。
6. 未完事项：下一步与论证停点。已完成或撤回事项退出活动清单；需要防止重复执行时保留简短关闭记录及来源。外部动作区分尚未执行、已提交、已确认与结果未知。

历史命令、旧授权和承诺作为历史材料承接，不能扩大当前操作权限。日期使用事件时间与已知 timezone；人的“那天夜里”可以保留，截止日期有歧义就标记，不按新窗口日期重算。

预算不足时先压缩重复、工具噪声和可定位的细节，保住纠正、约束、指代依赖、未完动作与重要经历的意义。无法同时保住时指出缺口，不用截字符串伪装成完整交接。
```

预算由调用者按最终装载通路给出，包含其他同时注入内容。`additionalContext` 的单字符串上限不是建议把摘要写满；文件化后的摘要不等于模型已经读过。归档用的索引标题、主题、覆盖范围与来源定位可以留在 sidecar，按需要装入，不能把一切检索 metadata 都塞进常驻提示。

这是内容合同。它不保证调用者有完整旧上下文、不保证原生 compact 使用这一 writer，也不负责停止旧窗、建立新 session 或提交 handoff。

## 给 curation writer 的候选正文

```text
判断本次材料中有没有值得长期保存或修订的记忆。先说明未来什么场景会需要它，再表达事件本身与意义；不要只把对话改写成标签。

每个候选包含：召回场景、简短标题、具体内容、来源定位、相关人或事、可能的提法，以及它是新记录还是对已有内容的修订。沿用接收 backend 的正式字段，不自行发明入库接口。

没有成熟的召回锚点时可以保留待整理证据，不强行入库，也不自动丢掉。项目事实由项目记录负责；同一事件的个人意义可以引用同一来源，不必为分类把事件拆到失去因果。

分别表达证据把握、有效时间、长期价值和是否待审。一次发生的事件也可以确定而重要。相同来源在多次摘要中出现，仍只算一次来源。

检索线索使用具体名称、情境和口语提法。排除词只处理已知歧义，不作为永久全局禁词。原话只有能对回来源时才放引号；事件时间与来源 ID 由可靠记录提供。

输出候选或修订建议；写入、去重、冲突处理、索引与成功回执由已有 backend 承担。摘要生成本身不触发持久写入。
```

## 一段材料，两种有用的输出

以下均为合成例子，**示范预期判断，不是模型实测回复**。

原事件：

```text
e1 用户：今天先做低对比度的卡片墙。我现在有点累，长期配色下次再决定。
e2 用户：周五只要本地草稿，不要发送。能导出自己的记录，是我愿意继续做这个项目的原因。
e3 用户：时间改到周日。先陪我把“能导出”和“维护起来麻烦”这个取舍想完。
```

| 去向 | 合理保留 | 应拒绝的变化 |
| --- | --- | --- |
| 下一窗 handoff | 卡片墙；周日；只做本地草稿；当下疲倦；可导出性与维护成本的讨论未完 | 固化长期低对比风格、沿用周五、把讨论写成迁移已批准 |
| 项目记录 | 当前交付范围、改期来源 e3、未定的设计取舍 | 把临时状态扩成永久项目约束 |
| 长期 Memory 候选 | e2 中“拥有并导出自己的记录”的意义；是否入库由既有 curation 流程判断 | 将三个事件编成三次独立确认、凭此认定所有产品都必须迁移 |

换窗要立即接住全部未完语义；长期库只在有未来用途时保存相应层次。两份派生内容保留相同来源，不必互相抢 canonical authority。

## 用已有语料反驳草案

复用 [continuity-cases.json](continuity-cases.json)，不另建一套 runner：C01 核指代，C02 核中间纠正，C03 核继承计数，C04 核动作状态，C05 核未交付附件，C06 核时间，C07 核讨论与氛围，C08 核最后的 reminder 变换。另在审阅时检查：

- 只有旧摘要、没有原话时，是否伪造“精确引用”；是否能保留暂未命名的事件。
- 确定但只发生一次的事件，是否被误标为低置信。
- 跨午夜的口语日期，是否保留解释依据与歧义，而不是猜一个日历日。
- 原始摘要、预算裁减后摘要、真正送出的 request 是否仍表达同一纠正和未完动作。

以上是尚未执行的语义判据。结构齐全、Markdown 有效或写满固定栏目，都不能证明续接质量。
